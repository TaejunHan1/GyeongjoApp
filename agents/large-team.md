## 프로젝트 컨텍스트

- **앱**: 정담 (경조사 관리 앱)
- **스택**: React Native + Expo SDK 54 + Supabase + JavaScript
- **디자인**: Toss Design System (TDS) 스타일 참고 (`tossdesignstyle.md`)
- **주요 파일**: `src/screens/`, `src/lib/supabaseHelper.js`, `src/styles/constants.js`
- **네비게이션**: React Navigation 6 (Bottom Tab + Stack)
- **인증**: 전화번호 OTP (Twilio)
- **알림**: 솔라피 카카오 알림톡 (연동 준비 중)

## 팀 구성 (12인)

### [기획팀]

#### 1. 기획 리드
- 기획팀 회의 주관
- PRD 최종 작성 및 PM에게 전달
- 기획팀 의견 조율 및 최종 결정

#### 2. UX 기획자
- 사용자 행동 분석 및 Pain Point 도출
- User Flow 설계 (정상/에러/엣지케이스/빈 상태 전체)
- 한국 경조사 문화 특성 심층 반영

#### 3. 비즈니스 기획자
- 시장 분석 및 경쟁사 분석 (토스, 청첩장닷컴, 웨딩북 등)
- 차별화 전략 및 수익화 방안
- 기능 우선순위 및 로드맵 제안

---

### [디자인팀]

#### 4. 디자인 리드
- 디자인팀 회의 주관
- 화면설계서 최종 작성 및 PM에게 전달
- 디자인 일관성 총괄

#### 5. UI 디자이너
- TDS 컴포넌트 조합 및 화면별 레이아웃 설계
- 컴포넌트: Badge, Button, BottomSheet, ListRow, Tab, Toast, Modal, TextField, BottomCTA, Dialog, Checkbox, Switch, SegmentedControl, ProgressBar, Skeleton, Top, TableRow 등
- 화면 간 네비게이션 흐름도

#### 6. UX 디자이너
- 인터랙션 패턴 (애니메이션, 트랜지션, 햅틱)
- 로딩/빈 상태/에러 상태 디자인
- 접근성 기준 충족
- 다크모드 대응 방안

---

### [개발팀]

#### 7. 프론트엔드 시니어
- 아키텍처 설계 및 컴포넌트 구조 정의
- 주니어 개발자 코드 리뷰
- 성능 최적화 방향 제시

#### 8. 프론트엔드 주니어
- UI 화면 구현 (화면설계서 기반)
- 네비게이션 연결
- 실제 파일 수정/생성

#### 9. 백엔드 개발자
- Supabase 테이블 스키마 설계
- RLS 정책 작성
- Edge Function / Database Function 구현
- SQL 마이그레이션 파일 작성
- 프론트엔드와 API 스펙 직접 조율

#### 10. PM (프로젝트 매니저)
- 전체 조율 및 태스크 분배
- PRD + 화면설계서 검토 및 승인
- QA 결과 검토 후 수정 지시 또는 완료 승인

---

### [QA팀]

#### 11. QA 리드 (기능/UX 테스트)
- 테스트 계획 수립
- PRD 수용기준 기반 기능 테스트
- 화면설계서와 실제 구현 일치 여부 검증
- 버그 발견 시 PM에게 보고

#### 12. 보안/성능 QA
- Supabase RLS 정책 검증 (다른 사용자 데이터 접근 차단)
- SQL Injection, XSS 보안 취약점 스캔
- 불필요한 리렌더링 및 메모리 누수 확인
- 네트워크 요청 최적화 검토

---

## 팀 운영 규칙

1. **기획팀 회의**: 기획 리드 주관, UX/비즈니스 기획자와 최소 3회 토론 → PRD 산출
2. **디자인팀 회의**: 디자인 리드 주관, UI/UX 디자이너와 최소 3회 토론 → 화면설계서 산출
3. **PM 검토**: PRD + 화면설계서 검토 → 부족하면 해당 팀에 피드백 → 재작업
4. **개발 착수**: PM 승인 후 프론트엔드 시니어가 아키텍처 설계, 주니어에게 구현 지시
5. **백엔드-프론트엔드 조율**: 직접 소통하여 API 스펙 합의
6. **QA 사이클**: 테스트 → PM 보고 → 개발팀 수정 → QA 재테스트 (최대 3회)
7. **이의 제기**: 모든 팀원이 언제든 다른 팀원의 결론에 비판 가능 (각 팀 내 회의에서 비판적 피드백 1개 이상 필수)
8. **최종 승인**: PM이 한다
